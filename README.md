# FastAPI Rate Limiter (Redis Sliding Window)

Небольшой сервис на FastAPI с ограничением частоты запросов (rate limiting) на основе Redis. Алгоритм — sliding window log через отсортированное множество (`ZSET`) Redis, реализован как переиспользуемая FastAPI-зависимость.

## Как это работает

Для каждой пары `(эндпоинт, IP-адрес клиента)` в Redis ведётся отсортированное множество `rate_limiter:{endpoint}:{ip_address}`, где:
- **member** — уникальный идентификатор запроса (`timestamp-random`);
- **score** — время запроса в миллисекундах.

При каждом запросе:
1. Из множества удаляются записи старше скользящего окна (`ZREMRANGEBYSCORE`);
2. Считается количество оставшихся запросов в окне (`ZCARD`);
3. Текущий запрос добавляется в множество (`ZADD`);
4. Ключу обновляется TTL (`EXPIRE`), чтобы неактивные клиенты не занимали память.

Все операции выполняются одним пайплайном Redis, что даёт атомарность на уровне запроса и минимизирует число round-trip'ов к Redis.

Если число запросов в окне достигает лимита — клиент получает `429 Too Many Requests`.

## Технологии

- FastAPI
- Redis (redis.asyncio)
- Python 3.11+

## Установка и запуск

1. Установите зависимости:
   ```bash
   pip install fastapi uvicorn "redis[hiredis]"
   ```

2. Запустите Redis (например через Docker):
   ```bash
   docker run -d -p 6379:6379 redis:7
   ```

3. Запустите сервер:
   ```bash
   uvicorn main:app --reload
   ```

4. Приложение доступно на [http://127.0.0.1:8000](http://127.0.0.1:8000), документация — на [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

## Эндпоинты

| Метод | Путь           | Лимит                  | Описание                          |
|-------|----------------|-------------------------|------------------------------------|
| POST  | `/sql_code`    | 5 запросов / 5 секунд   | Приём SQL-кода для обработки       |
| POST  | `/python_code` | 3 запроса / 10 секунд   | Приём Python-кода для обработки    |

Оба тела запроса ожидают JSON вида:
```json
{"code": "SELECT 1;"}
```

При превышении лимита возвращается:
```json
{"detail": "Превышено кол-во запросов, повторите позже"}
```
со статусом `429 Too Many Requests`.

## Добавление нового лимита

Лимит для нового эндпоинта задаётся фабрикой зависимости `rate_limiter_factory`:

```python
rate_limit_new = rate_limiter_factory("new_endpoint", max_requests=10, window_seconds=60)

@app.post("/new_endpoint", dependencies=[Depends(rate_limit_new)])
async def handler():
    ...
```

Каждый эндпоинт использует собственный ключ Redis (`rate_limiter:{endpoint}:{ip_address}`), поэтому лимиты разных маршрутов не пересекаются.

## Известные ограничения

- Идентификация клиента — по `request.client.host` (IP-адрес). За прокси/балансировщиком без передачи `X-Forwarded-For` все клиенты могут определяться одним IP.
- Подключение к Redis создаётся один раз через `lru_cache` и переиспользуется на всё время жизни приложения; при недоступности Redis запросы будут падать с ошибкой на уровне зависимости.
